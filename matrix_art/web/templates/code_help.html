What a Code effect is

A Code item is a Python script that draws one 64×64 RGB frame at a time. Matrix-Art runs the script in a separate effect process, calls render() repeatedly, and sends each frame to the panel.

The top-left pixel is (0, 0). The bottom-right pixel is (63, 63). RGB color values are normally 0 to 255.

red = (255, 0, 0)
green = (0, 255, 0)
blue = (0, 0, 255)
white = (255, 255, 255)
black = (0, 0, 0)

Minimum effect

The only required function is render(). This example clears the panel and lights one red pixel near the center.

def render(ctx, t, dt, frame, params):
    frame.fill(0, 0, 0)
    frame.set_pixel(32, 32, 255, 0, 0)

Function arguments

  • ctx contains display and timing values such as ctx.width, ctx.height, ctx.fps, and ctx.frame_index.
  • t is seconds since the effect started.
  • dt is seconds since the last frame. Use it for frame-rate-independent motion.
  • frame is the drawing buffer.
  • params contains default parameter values from PARAMS.
  • state is optional persistent storage returned by setup().
def render(ctx, t, dt, frame, params):
    x = int((t * 10) % ctx.width)
    frame.clear()
    frame.set_pixel(x, 32, 255, 120, 0)

Persistent state with setup()

Use setup() for values that need to survive between frames, such as position, velocity, particles, random seeds, or cached network data.

def setup(ctx):
    return {"x": 0, "direction": 1}


def render(ctx, t, dt, frame, params, state):
    state["x"] += state["direction"]

    if state["x"] <= 0 or state["x"] >= ctx.width - 1:
        state["direction"] *= -1

    frame.clear()
    frame.set_pixel(state["x"], 32, 0, 255, 80)

Frame drawing helpers

  • frame.fill(r, g, b): fill the whole frame with one color.
  • frame.clear(): fill the frame with black.
  • frame.set_pixel(x, y, r, g, b): draw one pixel.
  • frame.get_pixel(x, y): read one pixel as (r, g, b).
  • frame.set_rgb_bytes(data): replace the whole frame from packed row-major RGB bytes.
  • frame.set_rgb_array(array): replace the whole frame from a NumPy-style 64×64×3 uint8 array.
  • frame.fade(amount): multiply current frame brightness by amount.
  • frame.line(x0, y0, x1, y1, r, g, b): draw a line.
  • frame.rect(x, y, w, h, r, g, b, fill=False): draw a rectangle.
  • frame.circle(cx, cy, radius, r, g, b, fill=False): draw a circle.
def render(ctx, t, dt, frame, params):
    frame.clear()
    frame.line(0, 0, 63, 63, 255, 255, 255)
    frame.rect(6, 6, 20, 14, 255, 80, 0, fill=False)
    frame.circle(46, 32, 10, 80, 180, 255, fill=True)

Fast full-frame RGB paths

Matrix-Art supports three levels of frame rendering. Simple effects should use drawing helpers. Full-frame effects can replace the whole frame. Advanced NumPy effects can write directly into the current frame buffer.

PathBest forDifficulty
Drawing helpersLearning, shapes, small animationsEasiest
set_rgb_bytes() / set_rgb_array()Effects that build a completed output bufferModerate
rgb_buffer() / rgb_array()Advanced procedural effects and NumPy outputAdvanced
  • A 64×64 RGB frame is exactly 12,288 bytes.
  • Color order is RGB.
  • Pixel order is left-to-right, top-to-bottom.
  • The byte index for pixel (x, y) is (y * ctx.width + x) * 3.
def render(ctx, t, dt, frame, params):
    data = bytearray(ctx.width * ctx.height * 3)

    for y in range(ctx.height):
        for x in range(ctx.width):
            i = (y * ctx.width + x) * 3
            data[i] = x * 4
            data[i + 1] = y * 4
            data[i + 2] = 40

    frame.set_rgb_bytes(data)

Direct writable buffer path

The direct-buffer API exposes writable views into the current frame. These views are valid only during the current render() call, so do not store them in state.

  • frame.rgb_buffer(): writable byte-level memoryview.
  • frame.mutable_rgb(): alias for rgb_buffer().
  • frame.rgb_array(): writable NumPy view shaped (64, 64, 3) with dtype uint8.
def render(ctx, t, dt, frame, params):
    buf = frame.rgb_buffer()

    for y in range(ctx.height):
        for x in range(ctx.width):
            i = (y * ctx.width + x) * 3
            buf[i] = x * 4
            buf[i + 1] = y * 4
            buf[i + 2] = 80

For advanced NumPy effects, rgb_array() is the fastest path because it writes directly into Matrix-Art's current frame buffer.

import numpy as np

NAME = "Direct NumPy Gradient"
DEFAULT_FPS = 60


def setup(ctx):
    y, x = np.mgrid[0:ctx.height, 0:ctx.width]
    return {"x": x.astype(np.uint16), "y": y.astype(np.uint16)}


def render(ctx, t, dt, frame, params, state):
    rgb = frame.rgb_array()
    x = state["x"]
    y = state["y"]

    rgb[:, :, 0] = (x * 4 + int(t * 80)) & 255
    rgb[:, :, 1] = (y * 4 + int(t * 50)) & 255
    rgb[:, :, 2] = 80

Good direct-buffer effects cache coordinate grids, palettes, and lookup tables in state, then write the final RGB values into frame.rgb_array() each frame.

import numpy as np

NAME = "Direct Palette Example"
DEFAULT_FPS = 60


def make_palette():
    p = np.empty((256, 3), dtype=np.uint8)
    for i in range(256):
        p[i] = (i, 255 - i, (i * 2) & 255)
    return p


def setup(ctx):
    y, x = np.mgrid[0:ctx.height, 0:ctx.width]
    return {
        "x": x.astype(np.float32),
        "y": y.astype(np.float32),
        "palette": make_palette(),
    }


def render(ctx, t, dt, frame, params, state):
    rgb = frame.rgb_array()
    x = state["x"]
    y = state["y"]
    palette = state["palette"]

    index = ((np.sin(x * 0.15 + t * 2.0) + np.sin(y * 0.12 - t * 1.6) + 2.0) * 63.75).astype(np.uint8)
    rgb[:, :, :] = palette[index]

NumPy environment check

The Code runner uses Matrix-Art's virtual environment. NumPy must be installed there, even if it is available in another shell Python.

./.venv/bin/python -c "import sys; print(sys.executable); import numpy; print(numpy.__version__, numpy.__file__)"

From the project folder, install or refresh dependencies with:

./.venv/bin/python -m pip install -r requirements.txt
sudo systemctl restart matrix-art.service

Beginner example: sine wave

This example draws one animated wave. Change 12 to adjust height, or t * 4 to adjust speed.

import math


def render(ctx, t, dt, frame, params):
    frame.clear()

    for x in range(ctx.width):
        y = int(32 + math.sin(x * 0.25 + t * 4) * 12)
        frame.set_pixel(x, y, 0, 200, 255)

Beginner example: bouncing ball

This example uses dt so the ball moves by pixels per second, not pixels per frame.

def setup(ctx):
    return {"x": 12.0, "y": 16.0, "vx": 22.0, "vy": 15.0}


def render(ctx, t, dt, frame, params, state):
    state["x"] += state["vx"] * dt
    state["y"] += state["vy"] * dt

    if state["x"] < 2 or state["x"] > ctx.width - 3:
        state["vx"] *= -1
    if state["y"] < 2 or state["y"] > ctx.height - 3:
        state["vy"] *= -1

    frame.clear()
    frame.circle(int(state["x"]), int(state["y"]), 2, 255, 80, 160, fill=True)

Parameters

Effects may define PARAMS. Matrix-Art currently uses the default values. The format is designed so UI controls can be added later without changing the effect format.

PARAMS = {
    "speed": {"type": "float", "default": 20.0, "min": 1.0, "max": 80.0, "step": 1.0},
    "red": {"type": "int", "default": 255, "min": 0, "max": 255, "step": 1},
}


def render(ctx, t, dt, frame, params):
    speed = params.get("speed", 20.0)
    red = params.get("red", 255)
    x = int((t * speed) % ctx.width)
    frame.clear()
    frame.set_pixel(x, 32, red, 80, 20)

For experienced users

  • Code runs in a separate process from the web UI.
  • Each render starts with a fresh blank FrameBuffer.
  • The runner drops old frames if the effect produces frames faster than the display worker can use them.
  • Long blocking work inside render() will cause stutter.
  • Network calls should be done rarely and cached in state. The built-in weather example shows this pattern.
  • Code effects are regular Python and run locally on the Pi, so file and system access should be used carefully.

Testing and debugging

  • Check validates syntax without starting the effect.
  • Run Editor tests unsaved changes.
  • Save stores the code and regenerates its Library thumbnail from frame 10.
  • Use Current Display as Thumbnail is useful when startup frames are blank or unrepresentative.

Common beginner errors include missing colons, mismatched quotes, typos in helper names, variables used before assignment, and mixed tabs/spaces.

Practical tips

  • Start from a small working example, then change one thing at a time.
  • Keep full-screen loops simple. The panel has 4,096 pixels.
  • Use dt for movement math.
  • Use setup() for particles, balls, grids, random seeds, or cached network data.
  • Built-in modules like math, random, and time are good choices.
  • Lower the FPS if an effect is too heavy.
